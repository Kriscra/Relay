Giriş

Genel Bakış & Mimari Tasarım

Relay'in modüler altyapısı ve Paper/Folia odaklı mühendisliği.

Relay, modern Minecraft sunucu yazılımlarında (Paper, Purpur ve özellikle çok iş parçacıklı Folia) eklentiler arası entegrasyonu modern standartlara taşımak için geliştirilmiş açık kaynaklı bir servis çatısıdır.

Eski Bukkit mimarisinde geliştirilen çözümler, her eklentinin birbirinin .jar dosyasına doğrudan bağımlı olmasını veya ana sunucu thread'ini donduran senkron metotlar kullanmasını gerektiriyordu. Relay, mikroservis benzeri Pub/Sub EventBus ve Reaktif Promise Servis Kaydı ile eklentileri tamamen birbirinden bağımsız hale getirir.

Mimarinin Temel Taşı: İki Ayrı Modül
  • relay-api: Yalnızca arayüzleri ve veri modellerini barındıran, 40 KB'lık hafif SDK kütüphanesi. Eklenti geliştiricileri sadece bunu çeker.
  • relay-core: Sunucunun plugins/ klasörüne atılan, motoru STARTUP aşamasında ayağa kaldıran ana eklenti.

Çekirdek Sistem

ServiceRegistry API & Reaktif Mimari

Öncelik basamakları, yüklenme sırasından bağımsız servis tüketimi ve yaşam döngüsü.

1. Öncelik Kademeleri (ServicePriority)

Bir servis için birden fazla eklenti sağlayıcı kaydettiğinde, Relay otomatik olarak en yüksek önceliğe sahip sağlayıcıyı birincil seçer. Eğer birincil eklenti devre dışı kalırsa (reload veya stop), Relay sıradaki en yüksek öncelikli sağlayıcıya kesintisiz geri döner:

HIGHEST (100)
HIGH (50)
NORMAL (0)
LOW (-50)
FALLBACK (-100)

2. Metot Kataloğu

Metot İmzası Dönüş Tipi Açıklama
register(Class<T>, T, ServicePriority, Plugin) ServiceRegistration<T> Yeni bir servis sağlayıcısı kaydeder. Birincil değişirse PrimaryProviderChangedEvent fırlatır.
getProvider(Class<T>) Optional<T> Aktif en yüksek öncelikli birincil sağlayıcıyı anında senkron döndürür.
awaitService(Class<T>) CompletableFuture<T> Servis zaten kayıtlıysa anında, henüz kayıtlı değilse kaydedildiği an tamamlanan Promise.
onServiceReady(Class<T>, Consumer<T>) void Servis hazır olduğunda verilen lambda fonksiyonunu tetikler (Yüklenme sırası koruması).
getRegistration(Class<T>) Optional<ServiceRegistration<T>> Aktif sağlayıcının öncelik derecesi ve sağlayan eklenti metaverisini döndürür.
getRegistrations(Class<T>) Collection<ServiceRegistration<T>> Bu servis için kayıtlı tüm sağlayıcıların listesini (öncelik sırasına göre) döndürür.
unregister(Class<T>, T) boolean Belirli bir sağlayıcı örneğini kayıttan düşürür.
unregisterAll(Plugin) void Eklenti devre dışı kaldığında (PluginDisableEvent) otomatik çağrılır, bellek sızıntısını önler.

Örnek 1: Reaktif Servis Tüketimi (Load-Order Independent)

Diğer eklentinin sizden önce mi yoksa sonra mı başladığını düşünmenize gerek yok:

public class MyPlugin extends JavaPlugin {
    @Override
    public void onEnable() {
        // Ekonomi servisi sunucuda ne zaman hazır olursa (şimdi veya 5 saniye sonra) tetiklenir:
        RelayAPI.getServiceRegistry().onServiceReady(EconomyService.class, economy -> {
            getLogger().info("Ekonomi sistemi başarıyla bağlandı!");
            getLogger().info("Para Birimi: " + economy.getDefaultCurrency().displayName());
        });
    }
}

Örnek 2: Özel Bir Servis Yazıp Sisteme Öncelikli Kaydetme

Kendi özel arayüzünüzü tanımlayıp diğer eklentilere açabilirsiniz:

// 1. Özel Servis Arayüzü:
public interface DungeonBridge {
    CompletableFuture<Boolean> isDungeonActive(String dungeonId);
    CompletableFuture<Integer> getPlayerDungeonLevel(UUID playerId);
}

// 2. Kendi Eklentinizde Servisi Kaydetme:
RelayAPI.getServiceRegistry().register(
    DungeonBridge.class,
    new MyDungeonBridgeImpl(),
    ServicePriority.HIGH, // Yüksek öncelikle kaydol
    this
);

// 3. Başka Bir Eklentiden Kullanma:
RelayAPI.getServiceRegistry().getProvider(DungeonBridge.class).ifPresent(dungeon -> {
    dungeon.isDungeonActive("ancient_ruins").thenAccept(active -> {
        if (active) getLogger().info("Antik Harabeler zindanı şu anda açık!");
    });
});

Örnek 3: Birincil Sağlayıcı Değişimini Dinleme (Dynamic Failover)

@EventHandler
public void onProviderChange(PrimaryProviderChangedEvent event) {
    if (event.getServiceClass().equals(EconomyService.class)) {
        getLogger().warning("Ekonomi sağlayıcısı değişti!");
        getLogger().info("Eski Sağlayıcı Eklenti: " + (event.getOldProvider() != null ? event.getOldProvider().getPlugin().getName() : "Yok"));
        getLogger().info("Yeni Sağlayıcı Eklenti: " + (event.getNewProvider() != null ? event.getNewProvider().getPlugin().getName() : "Yok"));
    }
}

RelayMessenger API Referansı (Pub/Sub & RPC)

Tamamen bağımsız mikroservis veri köprüsü, konu tabanlı yayın ve zaman aşımı korumalı RPC.

1. Metot Kataloğu

Metot İmzası Dönüş Tipi Açıklama
publish(String, T, Plugin) void Konuya mesaj fırlatır. Arka plan thread havuzunda tüm abonelere non-blocking dağıtılır.
subscribe(String, Class<T>, Plugin, MessageListener) Subscription Konuyu dinlemeye başlar. Gelen nesne tip güvenli şekilde lambda fonksiyonuna iletilir.
request(String, REQ, Class<RESP>, Duration) CompletableFuture<RESP> Soru-Cevap (RPC). Karşı taraftan yanıt bekler. Süre dolarsa RequestTimeoutException atar.
handleRequest(String, Class<REQ>, Plugin, RequestHandler) Subscription RPC isteklerini asenkron yanıtlayan (CompletableFuture dönen) işleyici kaydeder.
handleRequestSync(String, Class<REQ>, Plugin, SyncRequestHandler) Subscription RPC isteklerini anında değer döndürerek senkron çözen işleyici kaydeder.
unsubscribeAll(Plugin) void Eklentiye ait tüm abonelikleri ve RPC işleyicilerini bellekten kaldırır.

Örnek 1: Pub/Sub Kanal Yayını (EventBus Modeli)

Bir klan eklentisi seviye atlama duyurusu yapar; görev ve skor tablosu eklentileri bağımsız olarak bu veriyi tüketir:

// Paylaşılacak Veri Modeli (Java Record):
public record ClanLevelUpData(String clanName, UUID leaderId, int newLevel) {}

// Yayınlayan Eklenti (Klan Eklentisi):
ClanLevelUpData payload = new ClanLevelUpData("Akıncılar", leader.getUniqueId(), 5);
RelayAPI.getMessenger().publish("clan:levelup", payload, this);

// Dinleyen Eklenti A (Görev Eklentisi):
RelayAPI.getMessenger().subscribe("clan:levelup", ClanLevelUpData.class, this, context -> {
    ClanLevelUpData data = context.getPayload();
    questManager.giveReward(data.leaderId(), 1000);
});

// Dinleyen Eklenti B (Discord / Webhook Eklentisi):
RelayAPI.getMessenger().subscribe("clan:levelup", ClanLevelUpData.class, this, context -> {
    ClanLevelUpData data = context.getPayload();
    discordBot.sendMessage("📢 " + data.clanName() + " klanı " + data.newLevel() + ". seviyeye ulaştı!");
});

Örnek 2: Zaman Aşımı Korumalı Mikroservis RPC (Request-Response)

Açık Artırma eklentisi, Banka eklentisine oyuncunun teklif verecek parası olup olmadığını sorar ve bakiye rezerve eder:

// İstek ve Yanıt Modelleri:
public record BidRequest(UUID playerId, BigDecimal bidAmount) {}
public record BidResponse(boolean approved, String failureReason) {}

// Banka Eklentisi (İsteği Yanıtlayan):
RelayAPI.getMessenger().handleRequest("auction:verify_bid", BidRequest.class, this, (ctx, req) -> {
    return bankService.checkAndLockFunds(req.playerId(), req.bidAmount())
        .thenApply(success -> success 
            ? new BidResponse(true, null) 
            : new BidResponse(false, "Yetersiz bakiye!"));
});

// Açık Artırma Eklentisi (Soru Soran):
BidRequest req = new BidRequest(player.getUniqueId(), BigDecimal.valueOf(5000));

// 3 saniye süre tanınır, yanıt gelmezse otomatik iptal edilir:
RelayAPI.getMessenger().request("auction:verify_bid", req, BidResponse.class, Duration.ofSeconds(3))
    .thenAccept(response -> {
        if (response.approved()) {
            player.sendMessage("§aTeklifiniz kabul edildi!");
        } else {
            player.sendMessage("§cTeklif reddedildi: " + response.failureReason());
        }
    })
    .exceptionally(err -> {
        player.sendMessage("§cBanka servisine ulaşılamadı (Zaman aşımı). Teklif iptal edildi.");
        return null;
    });
Finans

EconomyService API Referansı (Çoklu Para Birimi)

Kayıpsız BigDecimal aritmetiği, atomik transferler ve bağımsız para birimleri.

1. Neden double Değil de BigDecimal?

Java'da IEEE 754 standardındaki double türü ikili tabanda kayan nokta hesaplar. Örneğin 0.1 + 0.2 işleminin sonucu 0.30000000000000004 çıkar. Eski Vault eklentilerinde oyuncuların kuruşlarının kaybolması veya devasa ekonomilerde haksız para türemesinin sebebi budur. Relay, finans sektörünün altın standardı olan BigDecimal kullanarak %100 kayıpsız çalışır.

2. Metot Kataloğu

Metot İmzası Dönüş Tipi Açıklama
getDefaultCurrency() Currency Sunucunun birincil para birimini döndürür.
getCurrency(String) Optional<Currency> Özel bir para birimini kimliğine göre arar (Örn: "gold", "token", "crypto").
getBalance(UUID, Currency) CompletableFuture<BigDecimal> Oyuncunun belirli bir para birimindeki bakiyesini asenkron çeker.
has(UUID, BigDecimal, Currency) CompletableFuture<Boolean> Oyuncunun belirtilen miktarda parası olup olmadığını kontrol eder.
deposit(UUID, BigDecimal, Currency, String) CompletableFuture<EconomyResponse> Hesaba para ekler ve log açıklaması (reason) kaydeder.
withdraw(UUID, BigDecimal, Currency, String) CompletableFuture<EconomyResponse> Hesaptan para çeker. Yetersiz bakiye durumunda işlemi iptal eder.
transfer(UUID, UUID, BigDecimal, Currency, String) CompletableFuture<EconomyResponse> İki hesap arasında atomik (güvenli) transfer yapar. Bir taraf başarısız olursa işlem geri alınır.

Örnek 1: İki Farklı Para Birimiyle Alışveriş GUI'si

public void buyPremiumSword(Player player) {
    RelayAPI.getEconomy().ifPresent(econ -> {
        UUID uuid = player.getUniqueId();
        
        // 1. "token" adlı özel para birimini bul:
        Currency token = econ.getCurrency("token").orElseThrow();
        BigDecimal price = BigDecimal.valueOf(150); // 150 Token

        // 2. Asenkron bakiye kontrolü ve para çekme:
        econ.withdraw(uuid, price, token, "Marketten Kılıç Satın Alındı")
            .thenAccept(response -> {
                if (response.isSuccess()) {
                    giveSword(player);
                    player.sendMessage("§aKılıç satın alındı! Kalan Token: " + econ.format(response.balanceAfter(), token));
                } else {
                    player.sendMessage("§cİşlem başarısız: " + response.errorMessage());
                }
            });
    });
}

Örnek 2: Atomik Para Gönderme Komutu (/pay)

public void handlePayCommand(Player sender, Player target, BigDecimal amount) {
    RelayAPI.getEconomy().ifPresent(econ -> {
        Currency gold = econ.getDefaultCurrency();

        econ.transfer(sender.getUniqueId(), target.getUniqueId(), amount, gold, "Oyuncu /pay Transferi")
            .thenAccept(res -> {
                if (res.isSuccess()) {
                    sender.sendMessage("§a" + target.getName() + " oyuncusuna " + econ.format(amount) + " gönderdiniz.");
                    sender.sendMessage("§7Kalan Bakiyeniz: " + econ.format(res.balanceAfter()));
                    target.sendMessage("§a" + sender.getName() + " size " + econ.format(amount) + " gönderdi!");
                } else {
                    sender.sendMessage("§cTransfer yapılamadı: " + res.errorMessage());
                }
            });
    });
}

CooldownService API Referansı

Otomatik bellek tahliyesi (TTL), yüzde ilerleme ve bitiş bildirimleri.

1. Metot Kataloğu

Metot İmzası Dönüş Tipi Açıklama
setCooldown(UUID, String, Duration, Plugin, Consumer) CooldownEntry Oyuncuya bekleme süresi atar. Süre bittiğinde geri çağırma (callback) tetiklenir.
hasCooldown(UUID, String) boolean Oyuncunun aktif bir bekleme süresi olup olmadığını anında doğrular.
getRemaining(UUID, String) Duration Kalan süreyi Java Duration nesnesi olarak döndürür.
formatRemaining(UUID, String) String Kalan süreyi formatlar (Örn: "3.4s", "1m 20s", "2h 10m").
getProgress(UUID, String) double 0.0 (başlangıç) ile 1.0 (tamamlandı) arasında ilerleme yüzdesini döndürür.
clearCooldown(UUID, String) boolean Bekleme süresini erkenden sonlandırır ve zamanlayıcıyı iptal eder.
setGlobalCooldown(String, Duration, Plugin, Consumer) CooldownEntry Tüm sunucu geneli paylaşılan ortak bekleme süresi başlatır (Örn: Ejderha Etkinliği).

Örnek 1: ActionBar Üzerinde Canlı Yetenek İlerlemesi Gösterme

public void castDashAbility(Player player) {
    UUID uuid = player.getUniqueId();
    String key = "ability:dash";

    // 1. Kontrol:
    if (RelayAPI.getCooldowns().hasCooldown(uuid, key)) {
        String remaining = RelayAPI.getCooldowns().formatRemaining(uuid, key);
        player.sendActionBar(Component.text("§cDash henüz hazır değil! (" + remaining + ")"));
        return;
    }

    // 2. Yeteneği uygula:
    applyDashEffect(player);

    // 3. 8 saniyelik bekleme başlat ve süre bitince ses efekti çal:
    RelayAPI.getCooldowns().setCooldown(uuid, key, Duration.ofSeconds(8), this, expiredEntry -> {
        player.sendActionBar(Component.text("§a✦ Dash Yeteneği Tekrar Hazır! ✦"));
        player.playSound(player.getLocation(), Sound.ENTITY_EXPERIENCE_ORB_PICKUP, 1f, 1.5f);
    });
}

Örnek 2: Sunucu Geneli Ejderha Etkinliği Cooldown'ı (Global Scope)

public void triggerDragonSpawnEvent() {

    // Ejderhayı doğur ve 2 saatlik global bekleme başlat:

    });
}

SharedDataService API Referansı (Ortak Veri & TTL)

Tip güvenli anahtarlar, geçici TTL etiketleri ve canlı veri mutasyon gözlemcileri.

1. Metot Kataloğu

Metot İmzası Dönüş Tipi Açıklama
DataKey.of(namespace, key, type, defaultVal) DataKey<T> Tip güvenli, namespace çakışmasız statik anahtar tanımlar.
set(UUID, DataKey<T>, T, Plugin) void Oyuncuya bellek içi veri kaydeder. Gözlemcileri (observer) uyarır.
setTemporary(UUID, DataKey<T>, T, Duration, Plugin) void Otomatik süresi dolan geçici veri bağlar (Örn: Savaş etiketi). Süre bitince bellekten silinir.
get(UUID, DataKey<T>) Optional<T> Veriyi güvenle çeker. Süresi dolmuş veya hiç atanmamışsa Optional.empty() döner.
getOrKeyDefault(UUID, DataKey<T>) T Değer bulunamazsa anahtarın varsayılan (default) değerini anında döndürür.
observe(DataKey<T>, Plugin, DataChangeListener) Subscription Bu anahtar herhangi bir eklenti tarafından değiştirildiğinde anında tetiklenir.

Örnek 1: Savaş Etiketi (Combat Tag) ve Işınlanma Engeli

Savaş eklentisi 15 saniyelik etiket koyar; Işınlanma eklentisi oyuncunun savaşıp savaşmadığını kontrol eder:

// 1. Ortak Anahtar Tanımı:

public boolean canTeleport(Player player) {

public void onVipZoneEnter(Player player) {

Savaş & Takım

PartyService API Referansı (Dost Ateşi & Parti)

Sıfır-gecikmeli senkron dost ateşi koruması, zindan grupları ve takım yönetimi.

1. Sıfır-Gecikmeli (Lock-Free) Senkron Kontrol

Minecraft sunucularında savaş anında (örneğin kılıç savurma, ok isabeti, büyü fırlatma) saniyede binlerce EntityDamageByEntityEvent tetiklenir. Burada asenkron sorgu yapmak event'i zamanında iptal edemez; senkron veritabanı sorgusu yapmak ise tüm sunucuyu dondurur. Relay, kilitsiz (lock-free) O(1) arama ile bu kontrolü mikrosaniyenin altında yapar.

2. Metot Kataloğu

Metot İmzası Dönüş Tipi Açıklama
isFriendlySync(UUID damager, UUID victim) boolean Sıfır-Gecikmeli: İki oyuncu aynı partideyken ve dost ateşi kapalıysa true döner. Asla thread dondurmaz.
canDamageSync(UUID damager, UUID victim) boolean Hasar verilebilir mi kontrolü. !isFriendlySync(damager, victim) ifadesine eşittir.
createParty(UUID leaderId, String name, int maxSize) CompletableFuture<Party> Yeni bir parti oluşturur ve kurucuyu lider yapar.
getParty(UUID playerId) CompletableFuture<Optional<Party>> Oyuncunun içinde bulunduğu aktif partiyi döndürür.
inSameParty(UUID playerA, UUID playerB) CompletableFuture<Boolean> İki oyuncunun aynı partide olup olmadığını asenkron kontrol eder.
addMember(UUID partyId, UUID memberId) CompletableFuture<Boolean> Partiye üye ekler. Kapasite aşıldığında veya oyuncu partiliyse false döner.
removeMember(UUID partyId, UUID memberId) CompletableFuture<Boolean> Üyeyi çıkarır. Lider ayrılırsa liderliği devreder, son üye ayrılırsa partiyi dağıtır.
setFriendlyFire(UUID partyId, boolean enabled) CompletableFuture<Boolean> Parti üyelerinin birbirine hasar verip veremeyeceğini ayarlar.
disbandParty(UUID partyId) CompletableFuture<Boolean> Partiyi dağıtır ve tüm üyeleri serbest bırakır.

Örnek 1: Sıfır-Gecikmeli Hasar Engelleme (Damage Listener)

package com.example.combat;

import org.bukkit.entity.Player;
import org.bukkit.event.EventHandler;
import org.bukkit.event.EventPriority;
import org.bukkit.event.Listener;
import org.bukkit.event.entity.EntityDamageByEntityEvent;
import org.vrz.relay.api.RelayAPI;

public class FriendlyFireListener implements Listener {

    @EventHandler(priority = EventPriority.HIGH, ignoreCancelled = true)
    public void onPlayerDamage(EntityDamageByEntityEvent event) {
        if (!(event.getDamager() instanceof Player damager) || !(event.getEntity() instanceof Player victim)) {
            return;
        }

        RelayAPI.getParties().ifPresent(parties -> {
            // isFriendlySync: O(1) lock-free kontrol. Saniyede binlerce vuruşta thread dondurmaz:
            if (parties.isFriendlySync(damager.getUniqueId(), victim.getUniqueId())) {
                event.setCancelled(true);
                damager.sendMessage("§c" + victim.getName() + " takım arkadaşınız! Ona saldıramazsınız.");
            }
        });
    }
}

Örnek 2: Zindan Grubu Oluşturma & Toplu Işınlama

public void startDungeonRaid(Player leader) {
    RelayAPI.getParties().ifPresent(parties -> {
        parties.getParty(leader.getUniqueId()).thenAccept(optParty -> {
            if (optParty.isEmpty()) {
                leader.sendMessage("§cZindana girmek için bir partiye sahip olmalısınız!");
                return;
            }

            Party party = optParty.get();
            if (!party.isLeader(leader.getUniqueId())) {
                leader.sendMessage("§cSadece parti lideri zindan akınını başlatabilir!");
                return;
            }

            leader.sendMessage("§aZindan kapıları açılıyor! Parti üye sayısı: " + party.getSize());
            for (UUID memberId : party.getMembers()) {
                Player member = Bukkit.getPlayer(memberId);
                if (member != null && member.isOnline()) {
                    teleportToDungeonArena(member);
                    member.sendMessage("§eZindana ışınlandınız! Takım arkadaşlarınızı koruyun.");
                }
            }
        });
    });
}

Metrics & Telemetry Service (Performans & Telemetri)

Sunucu işlem sürelerini, sayaçları, bellek sayaçlarını nanosaniye hassasiyetinde ölçen ve TPS düşüşlerini yakalayan dahili telemetri motoru.

Try-with-resources Süre Ölçümü

MetricScope ile ek kod yükü olmadan fonksiyonların ne kadar sürdüğünü anında kayıt altına alın.

Yüzdelik Dilimler (p95 / p99)

Sadece ortalamayı değil; en yavaş %5 ve %1'lik uç gecikmeleri dairesel tampon bellek ile RAM şişirmeden hesaplar.

Otomatik Lag Uyarısı

Ana döngüde belirlenen eşiği (örn: 50ms) aşan ağır işlemler için anında konsola uyarı yazar ve PerformanceAlertEvent fırlatır.

Metot Referansı (API Reference)

Metot İmzası Dönüş Tipi Açıklama
startTimer(String name) MetricScope Ölçüm başlatır; try-with-resources ile kapanınca süreyi kaydeder.
profile(String name, Runnable task) void Verilen görevi çalıştırır ve süresini kaydeder.
profileSupplier(String name, Supplier<T>) <T> T Görevi çalıştırır, sonucunu döndürür ve süresini kaydeder.

getCount(String name) long Sayacın anlık toplam değerini döndürür.

İleri Düzey

Folia Çok Çekirdekli Mimari Güvenliği

Bölgesel iş parçacıkları (Region Threads) ve paralel veri bütünlüğü kuralları.

Folia, Minecraft dünyasını birden fazla bağımsız bölgeye (region) böler ve her bölgeyi bağımsız bir CPU çekirdeğinde çalıştırır. Klasik eklentilerin static değişkenleri veya senkron Bukkit eventleri Folia üzerinde veri bozulmasına (Race Condition) yol açar.

Relay içerisindeki tüm veri yapıları (ConcurrentHashMap, CopyOnWrite, Atomic referanslar) Folia'nın çok iş parçacıklı doğasına tam uyumlu olacak şekilde geliştirilmiştir.

Geliştiricilere Folia Tavsiyeleri:
  • Veritabanı veya karmaşık bakiye işlemlerini asla ana döngüde yapmayın; Relay'in CompletableFuture döndüren asenkron metotlarını kullanın.
  • Yüksek frekanslı combat olaylarında yalnızca Relay'in isFriendlySync gibi lock-free senkron metotlarını tercih edin.

  • Asenkron Uyarı Olayı: Sunucu akışını kilitlemeden arka planda PerformanceAlertEvent fırlatılır; Discord webhook veya yönetici bilgilendirmeleri bağlanabilir.

v1.0.0

İlk Kararlı Resmi Sürüm (Initial Stable Release)

📅 26 Eylül 2026 • Tag: v1.0.0 • JitPack: ok

Relay framework'ünün ilk ana sürümü. 2011'den kalma senkron Vault kütüphanesini geride bırakarak modern Paper, Purpur ve çok iş parçacıklı (multi-threaded region) Folia 1.21+ sunucularına endüstri seviyesinde entegrasyon altyapısı sunar.

Çekirdek Mimari & Folia Uyumluluğu

  • Çift Modüllü Yapı: Eklenti geliştiricileri için sıfır ağır bağımlılıklı, hafif relay-api SDK'sı (compileOnly) ve sunucu eklentisi relay-core.
  • STARTUP Yüklenme Döngüsü: Diğer eklentiler açılmadan önce en erken yaşam döngüsünde ayağa kalkar, NullPointerException riskini ortadan kaldırır.
  • Sıfır Bellek Sızıntısı (Zero-Leak): Eklentiler /reload veya devre dışı kaldığında tüm servisler, abonelikler, bekleme süreleri ve paylaşımlı veriler RAM'den otomatik temizlenir.
  • Folia Bölgesel İş Parçacığı Güvenliği: ConcurrentHashMap ve Atomic yapılarla Folia'nın bağımsız CPU çekirdeklerinde %100 Race Condition koruması.

Reaktif Servis Kayıt Sistemi (ServiceRegistry)

  • 5 Kademeli Öncelik Zinciri: HIGHEST, HIGH, NORMAL, LOW, FALLBACK. Üst düzey bir eklenti geldiğinde otomatik geçiş, kapandığında alt kademeye kesintisiz dönüş.
  • Yüklenme Sırası Bağımsız Tüketim: onServiceReady ve awaitService ile reaktif promise desteği.
  • Dinamik Yaşam Döngüsü Olayları: ServiceRegisteredEvent, ServiceUnregisteredEvent ve PrimaryProviderChangedEvent.

Mikroservis Pub/Sub & RPC Mesajlaşması (RelayMessenger)

  • Bağımsız EventBus: Eklentilerin birbirinin JAR dosyasına ihtiyaç duymadan tip güvenli nesnelerle konu (topic) tabanlı veri paylaşabilmesi.
  • Zaman Aşımı Korumalı RPC (Soru-Cevap): request(topic, req, type, timeout) ile REST API / Mikroservis modeli ve RequestTimeoutException güvenliği.
  • Senkron Hızlı Yanıtlayıcı: handleRequestSync ile anında dönüt sağlayan RPC işleyicisi.

Kayıpsız Çoklu Para Birimli Asenkron Ekonomi (EconomyService)

  • Kayıpsız BigDecimal Standardı: IEEE 754 double kuruş yuvarlama ve haksız para türeme açıklarını tamamen sonlandıran finansal aritmetik.
  • Sınırsız Çoklu Para Birimi: Altın, Bakiye, Kripto Token ve Etkinlik Puanı gibi onlarca para birimini tek standartta bağımsız yönetebilme (Currency).
  • Atomik İki Taraflı Transfer: transfer(from, to, amount, currency, reason) ile bir taraf başarısız olduğunda otomatik geri alma güvencesi.

Evrensel Bekleme Süresi Motoru (CooldownService)

  • Otomatik Bellek Tahliyesi (TTL): Süresi dolan cooldown kayıtlarının arka planda RAM'den sessizce silinmesi.
  • Görsel Yüzde İlerlemesi: BossBar ve ActionBar için 0.0 - 1.0 arası dolum yüzdesi (getProgress()).
  • Bitiş Bildirimi & Olayı: Lambda callback fonksiyonu ve sunucu geneli CooldownExpiredEvent fırlatıcı.
  • Global Kapsam: Tüm sunucu geneli paylaşılan etkinlik bekleme süreleri (setGlobalCooldown).

Tip Güvenli Ortak Bellek & Savaş Etiketi (SharedDataService)

  • Tip Güvenli Anahtarlar: String yazım hatalarını ve ClassCastException riskini önleyen DataKey<T> mimarisi.
  • Geçici TTL Etiketleri: Savaşa giren oyunculara otomatik süresi dolan 15 saniyelik savaş etiketi bağlayabilme (setTemporary).
  • Canlı Veri Gözlemcileri: Bir eklenti veriyi değiştirdiğinde diğer eklentilerin anında haberdar olması (observe ve DataChangeEvent).

Asenkron Yetki ve Rütbe Servisi (PermissionService)

Parti & Sıfır-Gecikmeli Dost Ateşi (PartyService)

  • Sıfır-Gecikmeli Senkron Kontrol: Saniyede binlerce vuruşun yapıldığı combat anlarında thread bekletmeyen, sıfır bellek tahsisli isFriendlySync ve canDamageSync.
  • Tam Parti Yaşam Döngüsü: Zindan grupları oluşturma, kapasite sınırları, lider devri, üye atma ve otomatik dağılma.
  • Dahili Fallback: Harici parti eklentisi olmasa dahi yerleşik thread-safe yöneticisi (DefaultPartyServiceImpl).
  • Parti Olayları: PartyCreatedEvent, PartyDisbandedEvent, PartyMemberJoinedEvent, PartyMemberLeaveEvent, PartyLeaderChangedEvent, PartyFriendlyFireToggleEvent.
