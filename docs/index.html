Mimari Farkı

Neden Vault Yerine Relay?

2011 yılında tasarlanan eski Vault mimarisi ile modern Paper/Folia odaklı Relay arasındaki temel farklar.

Özellik Vault (Eski Standart) Relay (Modern Standart)
İş Parçacığı (Threading) Senkron (Ana thread'i bekletir) %100 Asenkron & Non-Blocking (CompletableFuture)
Sunucu Desteği Tek çekirdekli Bukkit / Spigot Paper, Purpur ve Çok Çekirdekli Folia Uyumlu
Finansal Hassasiyet double (Kuruş yuvarlama/kayıp hataları) BigDecimal ile %100 kayıpsız aritmetik
Para Birimleri Yalnızca 1 adet para birimi Sınırsız Çoklu Para Birimi (Currency)
Eklentiler Arası İletişim Yok (Doğrudan .jar bağımlılığı zorunlu) Bağımsız Pub/Sub & Soru-Cevap (RPC) EventBus
Yüklenme Sırası (Load Order) NullPointerException riski Reaktif onServiceReady Promise mimarisi
Öncelik & Fallback Zinciri Sınırlı Bukkit önceliği Dinamik geçiş zinciri (HIGHEST ➔ FALLBACK)

Genel Bakış & Mimari

Relay'in kuruluş felsefesi ve teknik tasarım kararları.

Relay, Paper, Purpur ve çok iş parçacıklı (multi-threaded region) Folia sunucuları için sıfırdan geliştirilmiş yeni nesil bir servis köprüsü ve eklentiler arası iletişim omurgasıdır.

Minecraft sunucu ekosisteminde uzun yıllardır kullanılan Vault kütüphanesi, 2011 Spigot çağında tasarlanmıştır ve tüm işlemleri ana sunucu döngüsünde (Server Thread) senkron çalıştırır. Modern sunucularda veritabanı veya karmaşık ekonomi işlemleri yapıldığında sunucu TPS düşüşleri (lag spike) yaşar. Relay, bu sorunu %100 Non-blocking CompletableFuture mimarisi ile kökten çözer.

💡 Önemli Tasarım İlkesi: Relay, iki ayrı modülden oluşur. Eklenti geliştiricileri yalnızca 40 KB'lık bağımsız relay-api kütüphanesini kullanır. Sunucu sahipleri ise relay-core.jar eklentisini sunucularına yükler.

Çekirdek Sistem

Dinamik Reaktif Servis Kaydı

Öncelik zincirleri ve yüklenme sırası bağımsız servis tüketimi.

1. Reaktif Tüketim (onServiceReady)

Eklentinizin diğer eklentiden önce veya sonra başlaması önemli değildir. Servis kayıt edildiği an dinleyici fonksiyon tetiklenir:

import org.vrz.relay.api.RelayAPI;
import org.vrz.relay.api.economy.EconomyService;

RelayAPI.getServiceRegistry().onServiceReady(EconomyService.class, economy -> {
    getLogger().info("Ekonomi sistemi hazır! Varsayılan birim: " + economy.getDefaultCurrency().displayName());
});

2. Öncelikli Servis Kaydı

Kendi servisinizi kaydederken öncelik derecesi (Priority) belirtebilirsiniz:

import org.vrz.relay.api.RelayAPI;
import org.vrz.relay.api.service.ServicePriority;

// HIGHEST, HIGH, NORMAL, LOW, FALLBACK
RelayAPI.getServiceRegistry().register(
    EconomyService.class,
    new MyCustomEconomyProvider(),
    ServicePriority.HIGH,
    this
);
İletişim Omurgası

Pub/Sub & Soru-Cevap (RPC)

Eklentiler arası bağımsız mikroservis veri köprüsü.

1. Kanal Tabanlı Yayın (Publish / Subscribe)

// Yayınlayan Eklenti (Örn: Klan Eklentisi):
RelayAPI.getMessenger().publish("clan:levelup", new ClanLevelPayload("Akıncılar", 10), this);

// Dinleyen Eklenti (Örn: Skor Tablosu veya Görev Eklentisi):
RelayAPI.getMessenger().subscribe("clan:levelup", ClanLevelPayload.class, this, ctx -> {
    ClanLevelPayload data = ctx.getPayload();
    getLogger().info(data.clanName() + " klanı 10. seviyeye ulaştı!");
});

2. Asenkron Soru-Cevap (RPC)

Bir eklenti diğerine asenkron soru sorar, karşı taraf yanıt verir (Zaman aşımı korumalı):

// Soru soran eklenti (2 saniye zaman aşımı ile):
RelayAPI.getMessenger().request("player:reputation", playerId, Integer.class, Duration.ofSeconds(2))
    .thenAccept(rep -> player.sendMessage("İtibar puanınız: " + rep))
    .exceptionally(err -> {
        player.sendMessage("İtibar bilgisi alınamadı!");
        return null;
    });
Finansal Standart

Çoklu Para Birimli Asenkron Ekonomi

BigDecimal hassasiyeti ve CompletableFuture işlemleri.

RelayAPI.getEconomy().ifPresent(econ -> {
    UUID playerId = player.getUniqueId();
    BigDecimal amount = BigDecimal.valueOf(500.00);

    // Asenkron Para Yatırma
    econ.deposit(playerId, amount, "Görev Tamamlama").thenAccept(res -> {
        if (res.isSuccess()) {
            player.sendMessage("Hesabınıza " + econ.format(amount) + " yatırıldı!");
            player.sendMessage("Yeni bakiye: " + econ.format(res.balanceAfter()));
        } else {
            player.sendMessage("Hata: " + res.errorMessage());
        }
    });
});
Zaman Yönetimi

Evrensel Bekleme Süresi Motoru

Otomatik bellek tahliyesi ve ilerleme takibi.

UUID playerId = player.getUniqueId();
String key = "ability:dash";

// 1. Cooldown Kontrolü
if (RelayAPI.getCooldowns().hasCooldown(playerId, key)) {
    String remaining = RelayAPI.getCooldowns().formatRemaining(playerId, key);
    player.sendMessage("§cYetenek hazır değil! Kalan: " + remaining);
    return;
}

// 2. Cooldown Uygulama ve Bitiş Callback'i
RelayAPI.getCooldowns().setCooldown(playerId, key, Duration.ofSeconds(8), this, entry -> {
    player.sendMessage("§aDash yeteneğiniz tekrar hazır!");
});
Ortak Hafıza

Paylaşımlı Veri & TTL Savaş Etiketi

Eklentiler arası tip güvenli veri depolama ve canlı gözlemciler.

// 1. Tip güvenli anahtar tanımlama
DataKey<Boolean> COMBAT_TAG = DataKey.of("combat", "tagged", Boolean.class, false);

// 2. Savaşa giren oyuncuya 15 saniyelik geçici (TTL) etiket koyma
RelayAPI.getData().setTemporary(player.getUniqueId(), COMBAT_TAG, true, Duration.ofSeconds(15), this);

// 3. Işınlanma eklentisinden kontrol etme
if (RelayAPI.getData().getOrKeyDefault(player.getUniqueId(), COMBAT_TAG)) {
    player.sendMessage("§cSavaş halindeyken ışınlanamazsınız!");
}
Yetkilendirme

Asenkron Yetki ve Grup Servisi

TPS düşürmeyen LuckPerms uyumlu yetki kontrolü.

RelayAPI.getPermissions().ifPresent(perms -> {
    UUID playerId = player.getUniqueId();

    perms.hasPermission(playerId, "vip.fly").thenAccept(canFly -> {
        if (canFly) player.setAllowFlight(true);
    });

    perms.getPrimaryGroup(playerId).thenAccept(group -> {
        perms.getPrefix(playerId).thenAccept(prefix -> {
            player.sendMessage("Rütbeniz: " + prefix + group);
        });
    });
});
Takım & Savaş

Parti ve Sıfır-Gecikmeli Dost Ateşi

Yüksek frekanslı combat kontrolleri ve zindan grubu yönetimi.

Savaş Olayında Sıfır-Gecikmeli (Lock-Free) Kontrol

@EventHandler(priority = EventPriority.HIGH, ignoreCancelled = true)
public void onDamage(EntityDamageByEntityEvent event) {
    if (event.getDamager() instanceof Player damager && event.getEntity() instanceof Player victim) {
        RelayAPI.getParties().ifPresent(parties -> {
            // isFriendlySync: O(1) sabit sürede kontrol eder, asla thread dondurmaz:
            if (parties.isFriendlySync(damager.getUniqueId(), victim.getUniqueId())) {
                event.setCancelled(true);
                damager.sendMessage("§cTakım arkadaşına saldıramazsın!");
            }
        });
    }
}
Çok Çekirdekli Mimari

Folia & Thread Güvenliği

Çok bölgeli eşzamanlı dünyalarda veri güvenliği.

Folia, Minecraft sunucularını bölgelere (region) bölerek her bölgeyi bağımsız CPU çekirdeklerinde çalıştırır. Klasik eklentilerin static değişkenleri ve senkron Bukkit eventleri Folia üzerinde veri bozulmasına (Race Condition) yol açar.

Relay'in tüm servisleri, ConcurrentHashMap, Atomic referanslar ve non-blocking CompletableFuture yapılarıyla güçlendirilmiştir. Bu sayede Folia'nın paralel çekirdeklerinde %100 güvenli çalışır.
